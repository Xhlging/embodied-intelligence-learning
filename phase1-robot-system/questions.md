# Phase 1: 认识机器人系统 — 问题回答

> 阅读材料: 《Robotics: Modelling, Planning and Control》(Sciavicco) 节选

---

## 问题 1: 什么是具身智能特有的，深度学习中不会考虑的？

深度学习通常处理的是**抽象的数据空间**——图像像素矩阵、文本 token 序列、特征向量等。数据和模型存在于硅基芯片中，没有物理形态。具身智能则不同，它必须面对以下深度学习不会考虑的问题：

### 1. 物理载体（Mechanical System）

机器人有真实的机械结构——由连杆（links）和关节（joints）组成的运动链。这个"身体"有质量、惯性、摩擦、弹性形变等物理属性。深度学习的模型没有重量，不会磨损，不会发热。

### 2. 运动学与动力学约束

- **运动学（Kinematics）**: 关节空间（joint space）与操作空间（operational space）之间的映射关系。关节角度 $q$ 如何决定末端执行器的位姿 $x_e$？（正向运动学）；反之，要让末端到达目标位置，关节该如何转动？（逆运动学）
- **动力学（Dynamics）**: 力/力矩如何产生运动？$$B(q)\ddot{q} + C(q,\dot{q})\dot{q} + g(q) = \tau$$ 惯性矩阵 $B$、科里奥利力 $C$、重力 $g$——这些都是纯深度学习不需要关心的。
- **工作空间（Workspace）**: 机器人能到达的空间是有物理边界的，受关节限位和机械结构限制。

### 3. 感知-行动闭环（Sensorimotor Loop）

机器人系统是一个**闭环**（图 1.1）：
- **感知系统（Sensory System）**: 本体感知传感器（编码器测关节角度）和外感知传感器（摄像头、力传感器）实时采集数据
- **控制系统（Control System）**: 根据感知信息生成控制指令
- **执行系统（Actuation System）**: 伺服电机、减速器、传动装置将指令转化为物理运动
- 这个闭环需要**实时运行**（毫秒级），深度学习离线训练没有这个约束

### 4. 安全性和柔顺性

机器人可能伤害人类——阿西莫夫三大定律的根源。物理交互意味着需要：
- **柔顺控制（Compliance Control）**: 不是僵硬地执行轨迹，而是对环境力做出顺应
- **阻抗控制（Impedance Control）**: 调节机器人表现出的"硬度"
- **力控制（Force Control）**: 精确控制接触力（如抓取易碎物品）

### 5. 欠驱动与非完整约束

移动机器人可能存在**非完整约束（Nonholonomic Constraints）**: 不能瞬时侧移（如汽车），但可以通过一系列操作最终到达。这种"能做但受限"的特性在深度学习中没有对应。

### 6. 模型不确定性

真实世界的物理参数（摩擦系数、负载质量、传感器噪声）无法精确获知，需要**鲁棒控制**和**自适应控制**。深度学习的"域迁移"与之类似但本质不同——一个是统计分布偏移，一个是物理参数变化。

## 问题 2: 什么是 policy，如何设计一个 policy？

### Policy 的定义

Policy（策略）$\pi$ 是一个**从状态（或观测）到动作的映射**:

$$\pi: \mathcal{S} \rightarrow \mathcal{A}, \quad a = \pi(s)$$

其中:
- $s \in \mathcal{S}$ 是状态空间（如关节角度、末端位姿、视觉图像）
- $a \in \mathcal{A}$ 是动作空间（如关节力矩、关节速度、末端位移）

在机器人语境下，policy 本质上就是**控制律（Control Law）**——给定当前机器人状态和目标，输出应该执行什么动作。

### Policy 在机器人系统中的位置

参考教材的建模-规划-控制框架:

$$\text{Planning} \rightarrow \text{参考轨迹 } x_d(t) \rightarrow \boxed{\text{Policy } \pi} \rightarrow \text{控制指令 } \tau \rightarrow \text{Robot} \xrightarrow{\text{传感器}} \text{反馈 } x(t) \rightarrow \boxed{\text{Policy } \pi}$$

Policy 就是控制系统的核心：接收规划器给出的期望轨迹和传感器反馈的当前状态，计算执行指令。

### 如何设计一个 Policy

#### 方法一: 基于模型（Model-Based）

利用机器人的数学模型直接推导控制律:

1. **运动学控制**: 已知期望末端位姿 $x_d$，通过逆运动学求解期望关节角 $q_d$，再用 PID 控制跟踪 $q_d$
2. **动力学控制**: 建立动力学模型 $B\ddot{q} + C\dot{q} + g = \tau$，设计计算力矩控制器:
   $$\tau = B(q)(\ddot{q}_d + K_v\dot{e} + K_p e) + C(q,\dot{q})\dot{q} + g(q)$$
   其中 $e = q_d - q$ 为跟踪误差

#### 方法二: 基于学习（Learning-Based）

1. **模仿学习（Imitation Learning）**: 人类遥操作机器人完成抓取任务，收集 $(s, a)$ 数据对，用神经网络拟合 $\pi_\theta(s) \approx a$
   - 这就是 ACT（Action Chunking with Transformers）的思路——将 Transformer 用作 policy 网络
2. **强化学习（Reinforcement Learning）**: 让机器人在仿真中试错，通过奖励信号 $r(s, a)$ 学习最优 policy $\pi^*$

#### 方法三: 混合方法

结合模型的先验知识和学习的数据驱动能力:
- 用模型做前馈补偿（feedforward），用学习做残差修正（residual）
- Mole-VLA 的做法: 在大规模机器人数据上预训练 VLA 模型，然后在新环境微调

### Policy 设计中的核心考虑

| 因素 | 说明 |
|------|------|
| **动作空间选择** | 关节空间（joint space）还是操作空间（operational space）？直接影响控制精度和复杂度 |
| **反馈频率** | 视觉反馈可能是 30Hz，关节编码器可达 1kHz，多模态时间同步是挑战 |
| **安全约束** | 力/速度上限、关节限位、碰撞避免必须内建到 policy 中 |
| **泛化能力** | 新物体、新环境、新光照条件下 policy 是否仍然有效？ |

## 问题 3: "具身"体现在什么地方？

"具身"（Embodiment）的核心在于**智能不是纯粹的计算，而是通过身体与物理世界互动产生的**。具体体现在以下层面:

### 1. 物理身体决定了感知的边界

- 机器人的**传感器配置**决定了它能"看到"什么: 关节编码器告诉你手臂在哪（本体感知），腕部摄像头告诉你手前面有什么（外感知），力传感器告诉你抓得紧不紧
- 人类看不见红外线，机器人配备红外相机就能——"身体"的硬件配置直接定义了感知的上限
- 教材中提到的**操作空间（Operational Space）** 和**工作空间（Workspace）** 就是身体的物理边界

### 2. 物理身体决定了行动的可能

- 一个 6-DOF 机械臂能做的事情和一个 SCARA 机器人完全不同——**机械结构即能力边界**
- 教材中的分类：笛卡尔型、圆柱型、球型、SCARA、拟人型——每种构型有不同的工作空间形状和灵巧度（dexterity）
- 拟人型（anthropomorphic）最灵巧但精度分布不均；笛卡尔型精度最高但灵巧度最低——**身体结构即约束**

### 3. 物理定律是必须遵守的硬约束

- $$B(q)\ddot{q} + C(q,\dot{q})\dot{q} + g(q) = \tau$$
- 惯性、重力、科里奥利力不是可选的超参数——它们是物理现实，不遵守就会控制失效
- 深度学习可以通过增大模型或数据来绕过很多问题，但物理定律不能——你绕不过去

### 4. 行动影响感知，感知驱动行动——闭环耦合

- 机器人推一个物体 → 物体移动 → 视觉观测变化 → 调整推力 → ...
- 这不是离线数据集的 IID 采样，而是**序列决策中的分布漂移**——动作改变环境，环境改变观测分布
- 教材中提到的**视觉伺服（Visual Servoing）** 就是典型例子: 相机观测误差直接反馈到运动控制

### 5. 时间是不可压缩的

- 抓取一个物体必须在毫秒级精度内协调多关节运动
- 控制频率（通常是 100Hz-1kHz）决定了系统的稳定性和响应能力
- 深度学习训练的"一个 epoch 跑多久"是可伸缩的，但机器人控制的控制周期是物理硬约束

### 6. 环境是部分可观测且动态变化的

- 你永远无法获得环境的完整状态——光照变化、物体变形、传感器噪声
- 教材区分了**结构化环境**（工业机器人，已知布局）和**非结构化环境**（先进机器人，未知或动态变化）——深度学习的训练集通常是固定的，但物理环境是持续变化的

## 问题 4: 这些东西将来怎么影响你训练一个能抓东西的机器人？

从教材的**建模-规划-控制（Modelling-Planning-Control）**框架出发，训练一个抓取机器人时每个环节都会产生影响:

### Modelling（建模）的影响

| 必须建模的内容 | 抓取任务中的体现 |
|--------------|-----------------|
| **运动学模型** | 给定关节角度 $q$，末端执行器（手）在什么位置和姿态？——用 DH 参数建立正向运动学，才能知道手能不能够到物体 |
| **动力学模型** | 手臂抬起来需要多大扭矩？加速度不能超过多少？——否则电机过载或运动抖震 |
| **传感器模型** | 摄像头标定、力传感器零漂、编码器分辨率——直接影响观测质量 |
| **物体模型** | 目标物体的几何形状、质量、表面摩擦——决定怎么抓（抓取点选择） |

### Planning（规划）的影响

1. **轨迹规划（Trajectory Planning）**: 从当前位置到抓取点，需要生成一条平滑的路径（关节空间或笛卡尔空间），满足速度和加速度约束。教材第 4 章的方法（点对点运动、多路径点插值）直接适用
2. **抓取规划（Grasp Planning）**: 基于物体模型（或视觉观测）选择稳定的抓取位姿——考虑力封闭（force closure），确保物体不会滑落
3. **避障**: 环境中可能有其他物体，规划路径时必须避开

### Control（控制）的影响

1. **选择动作空间**: 
   - 关节空间控制（Joint Space）: 直接控制每个关节的位置/速度/力矩 → 更底层，更精确
   - 操作空间控制（Operational Space）: 控制末端执行器在笛卡尔空间的位姿 → 更直观，需要逆运动学
   - **对于抓取任务**: 接近阶段用操作空间控制（"把手移到物体上方 5cm"），抓取闭合阶段用力控制（"以 5N 的力闭合手指"）

2. **力控制至关重要**: 
   - 抓太轻 → 物体滑落
   - 抓太重 → 损坏物体（特别是易碎品）
   - 需要**混合力/位置控制（Hybrid Force/Motion Control）** 或**阻抗控制（Impedance Control）**

3. **视觉伺服（Visual Servoing）**: 如果物体位置不确定，用摄像头实时引导手向物体移动

### 对训练的具体影响

从具身智能（VLA / ACT / Mole-VLA）角度:

1. **Observation 设计**: 
   - 必须包含: 关节角度 $q$、关节速度 $\dot{q}$、末端位姿 $x_e$（本体感知）
   - 可选包含: RGB 图像、深度图、力/力矩读数（外感知）
   - 与纯视觉的深度学习不同——**状态向量 + 视觉的多模态融合**是必须的

2. **Action 设计**: 
   - 输出什么？关节角度增量 $\Delta q$？末端位姿增量 $\Delta x_e$？力矩 $\tau$？
   - ACT 使用**动作分块（Action Chunking）**——一次预测多个未来动作，解决高频控制与低频推理的不匹配

3. **环境交互**: 
   - 仿真环境中训练 → 现实中部署 = 面临 **sim-to-real gap**: 物理参数不匹配、视觉差异、动力学不精确
   - Mole-VLA 的任务就是在**新仿真环境**（非训练环境）跑通——这本质上是在测试模型的泛化能力

4. **安全与约束**: 
   - 关节限位、力矩上限、末端速度上限必须硬编码
   - 抓取接触力需要柔顺性——不能像分类问题那样"尽量提高置信度"就行

### 总结: 从深度学习到具身智能的思维转变

| 维度 | 深度学习思维 | 具身智能思维 |
|------|------------|------------|
| 输入 | 固定大小的图像/文本 | 多模态流数据（图像 + 关节状态 + 力反馈） |
| 输出 | 类别标签/生成文本 | 连续控制指令（物理量，有物理意义） |
| 评价 | Accuracy / Loss | 任务成功率 + 轨迹平滑度 + 力控精度 |
| 约束 | 无 | 物理定律、硬件限制、安全约束 |
| 部署 | 服务器推理 | 实时嵌入式系统 |
| 迭代 | 改模型改数据 | 改模型 + 改控制器 + 改机械设计 |

**教材的框架是基础底座**——不懂运动学，就无法确定 policy 的输入输出；不懂动力学，就无法理解为什么某些动作在物理上不可行；不懂控制理论，就无法设计稳定可靠的闭环系统。而深度学习的角色是在这个物理框架之上提供**感知能力和决策能力**——两者结合，才是具身智能。
